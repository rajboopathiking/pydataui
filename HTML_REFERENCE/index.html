    HTML Reference for Developers

    This guide covers the HTML contract behind PyDataUI: how Python components become markup, which semantic tags are available, how attributes are normalized, and where the security boundaries are. It is intended for application developers building custom layouts and for contributors extending the component system.

    For the higher-level customization workflow, start with UI Customization & Tailwind. For design tokens and stylesheet internals, see the CSS Reference.

    1. Rendering Model

    PyDataUI does not use a client-side component runtime or a template language. Every component renders to an HTML string on the server.

    Python component tree
        |
        v
Component.render(state_snapshot)
        |
        +--> _build_attrs()      ids, classes, styles, hx-* attributes
        +--> _render_children()  escaped text, child components, state values
        |
        v
HTML string
        |
        +--> full document shell (initial page load)
        +--> HTML fragment      (HTMX event response)

    The main implementation points are:

    File Responsibility
    pydataui/components/base.py Component, attribute rendering, escaping, child rendering, RawHtml
    pydataui/components/html.py Semantic HTML and SVG tag classes
    pydataui/compiler/templates.py Full document shell and application-level <head>
    pydataui/compiler/renderer.py Page and fragment rendering
    pydataui/utils.py escape_html, ID generation, value conversion

    An HTMX event returns a fragment, not a complete page. The fragment is swapped into #pdu-root; therefore a component must render correctly both inside the initial document and on its own.

    2. Document Shell

    The application shell is generated by get_base_html() in pydataui/compiler/templates.py. Its relevant structure is:

    <html class="dark"> <!-- only when App(theme="dark") -->
  <head>
    <script src="https://cdn.tailwindcss.com"></script>
    <script>tailwind.config = {...};</script>
    <style>
      :root { /* shadcn design tokens */ }
      /* custom_css */
    </style>
    <script src="/_pdu/static/htmx.min.js"></script>
    <link rel="stylesheet" href="/_pdu/static/pydataui.css">
    <!-- App(stylesheets=[...]) -->
    <!-- App(head=...) -->
  </head>
  <body class="min-h-screen" hx-headers='{"X-CSRF-Token":"..."}'>
    <div id="pdu-root" class="min-h-screen">
      <!-- page content -->
    </div>
  </body>
</html>

    Key contracts:

    • #pdu-root is the default HTMX target and the default hx-include source.
    • hx-headers on <body> carries the CSRF token for event requests.
    • App(stylesheets=[...]) loads after the framework stylesheet.
    • App(custom_css="...") is injected before HTMX and before pydataui.css.
    • App(head="...") is the last item in <head>.

    3. Common Component Properties

    Every Component accepts the following arguments:

    Argument Output Notes
    id id="..." Generated as pdu-<8 hex chars> when omitted. Supply your own for anchors, labels, tests, or JavaScript hooks.
    class_name Appended to class="..." Framework classes come first, then your Tailwind or custom classes.
    style style="..." A string is emitted as-is. A dict is joined with ;. Numeric values receive a px suffix. Dict keys are literal CSS property names.
    hidden No output hidden=True removes the component and its subtree from the response; it does not render the HTML hidden attribute.
    **props HTML attributes snake_case becomes kebab-case; data_* becomes data-*.
    on_* HTMX attributes Event handlers are converted to hx-* attributes and are never emitted as inline JavaScript.

    Examples:

    from pydataui.html import Section, P

Section(
    P("Rendered with a custom class and inline width."),
    id="quality-panel",
    class_name="pdu-p-lg bg-slate-50",
    style={"max-width": "48rem", "margin-top": 16},
)

    The numeric 16 becomes 16px.

    Attribute Normalization

    Python input HTML output
    aria_label="Quality" aria-label="Quality"
    data_action="refresh" data-action="refresh"
    data_testid=True data-testid=""
    disabled=True disabled
    disabled=False Omitted
    required=True required
    class_name="mt-4" Appended to the generated class list

    Boolean HTML attributes are emitted correctly instead of becoming disabled="False". Supported boolean attributes include disabled, required, readonly, checked, selected, autofocus, multiple, hidden, open, novalidate, defer, async, loop, autoplay, controls, and muted.

    None and False prop values are omitted. Strings and other values are escaped before being written into attributes.

    4. Semantic HTML Tags

    Import tags from pydataui.html:

    from pydataui.html import Section, Header, Nav, Main, Article, Aside, Footer
from pydataui.html import Div, Span, P, H1, H2, H3, H4, H5, H6
from pydataui.html import A, Ul, Ol, Li, Strong, Em, CodeTag, Pre, Hr, Br

    Structure and Text

    Class Element Purpose
    Div <div> Generic block container
    Span <span> Generic inline container
    Section <section> Thematic section
    Article <article> Self-contained content
    Header <header> Introductory content
    Footer <footer> Footer content
    Main <main> Primary page content
    Nav <nav> Navigation links
    Aside <aside> Complementary content
    P <p> Paragraph
    H1–H6 <h1>–<h6> Heading levels
    Strong <strong> Important text
    Em <em> Emphasized text
    CodeTag <code> Inline code
    Pre <pre> Preformatted block
    Hr <hr> Thematic break
    Br <br> Line break

    Links and Lists

    Class Element Special arguments
    A <a> href (defaults to "#")
    Ul <ul> None
    Ol <ol> None
    Li <li> None 
    A("View catalog", href="/catalog", target="_blank", rel="noopener")

    SVG

    Class Element Special arguments
    Svg <svg> viewBox (default "0 0 24 24"), fill (default "none"), stroke (default "currentColor")
    Path <path> d
    Circle <circle> cx, cy, r
    Rect <rect> x, y, width, height
    Line <line> x1, y1, x2, y2 
    from pydataui.html import Svg, Path

icon = Svg(
    Path(d="M13 10V3L4 14h7v7l9-11h-7z"),
    class_name="h-6 w-6 text-amber-500",
)

    The optional Path, Circle, Rect, and Line coordinates are only added when truthy. Values such as viewBox are preserved with their HTML attribute casing.

    Forms

    Class Element Special arguments
    FormTag <form> None; pass method, action, etc. as props
    ButtonTag <button> type (default "button")
    InputTag <input> type (default "text"); void element
    LabelTag <label> None
    TextareaTag <textarea> None
    SelectTag <select> None
    OptionTag <option> value

    For for on a label, use a dict because for is a Python keyword:

    LabelTag("Search", **{"for": "catalog-search"})
InputTag(id="catalog-search", type="search", name="q", placeholder="Search tables")

    Tables

    Class Element
    TableTag <table>
    TheadTag <thead>
    TbodyTag <tbody>
    TrTag <tr>
    ThTag <th>
    TdTag <td>

    Use scope="col" or scope="row" on header cells for accessible tables.

    5. Children, Values, and Escaping

    Children can be components, strings, numbers, lists, tuples, None, StateVarRef values, or callables that accept the state snapshot.

    from pydataui.html import Article, H2, P

Article(
    H2("Orders"),
    "Today's volume: ",
    1250,
    P("Compared with yesterday: ", order_delta),
)

    Rendering rules:

    • None children are skipped.
    • Nested lists and tuples are flattened one level.
    • Component children render recursively.
    • User-provided text is escaped with html.escape(..., quote=True).
    • Attribute values are escaped before output.
    • Callable children are invoked with the state snapshot.
    • StateVarRef children resolve against the current state snapshot.

    This means this input:

    P("Use <table> & <script> safely")

    produces escaped text content, not executable markup:

    <p id="pdu-..." class="pdu">Use &lt;table&gt; &amp; &lt;script&gt; safely</p>

    Raw HTML

    RawHtml and its alias Html bypass escaping:

    from pydataui import Html

Html('<div class="trusted-embed">...</div>')

    Only use these for trusted templates, pre-sanitized content, or third-party embeds you control. Do not pass user input directly to RawHtml. Prefer normal components for user-derived values.

    6. Complete Rendered Example

    from pydataui.html import Section, H1, P, A, ButtonTag

Section(
    H1("Quality overview"),
    P("All checks passed.", class_name="text-muted-foreground"),
    A("Open catalog", href="/catalog", target="_blank", rel="noopener"),
    ButtonTag("Refresh", type="button", data_action="refresh", disabled=False),
    class_name="pdu-p-lg",
    style={"max-width": "48rem"},
)

    Representative output (IDs vary per instance):

    <section id="pdu-55a67749" class="pdu pdu-p-lg" style="max-width: 48rem">
  <h1 id="pdu-66d947a8" class="pdu">Quality overview</h1>
  <p id="pdu-ab69fb02" class="pdu text-muted-foreground">All checks passed.</p>
  <a id="pdu-f024984e" class="pdu" target="_blank" rel="noopener" href="/catalog">Open catalog</a>
  <button id="pdu-ed1fcf83" class="pdu" data-action="refresh" type="button">Refresh</button>
</section>

    Every component receives the base pdu class. Framework components append their own classes, and class_name is appended last.

    7. State and Event Attributes

    State values can appear in text, props, and attributes:

    from pydataui import State
from pydataui.html import P, ButtonTag

class CounterState(State):
    count: int = 0

    def increment(self):
        self.count += 1

P("Count: ", CounterState.count)
ButtonTag("Increment", on_click=CounterState.increment)

    Event handlers render as HTMX attributes:

    <button
  id="pdu-e918535d"
  class="pdu"
  hx-post="/_pdu/event/CounterState/increment"
  hx-target="#pdu-root"
  hx-swap="innerHTML"
  hx-trigger="click"
  hx-include="#pdu-root"
  type="button">Increment</button>

    Do not hand-write these hx-* attributes for state methods. Use on_click=, on_change=, and the other supported event arguments so routing and CSRF behavior stay consistent.

    8. Extending HTML Components

    Subclass Component to add a semantic wrapper or a project-specific primitive:

    from pydataui import Component

class StatusPill(Component):
    tag = "span"

    def __init__(self, label, tone="success", **kwargs):
        super().__init__(label, **kwargs)
        self.tone = tone

    def _get_classes(self):
        return super()._get_classes() + [
            "pdu-badge",
            f"pdu-badge-{self.tone}",
        ]

    Usage:

    StatusPill("Healthy")

    Keep behavior server-side. If a component needs interactivity, express it through state methods and event handlers rather than injecting JavaScript. For a full CSS component checklist, see Extending the CSS Layer.

    9. Accessibility Checklist

    • Prefer semantic elements (button, nav, main, section, table) over generic div structures.
    • Always provide a type for ButtonTag; the default is "button", which avoids accidental form submission.
    • Associate labels and inputs with matching id/for values.
    • Use table headers with scope="col" or scope="row".
    • Give SVGs a title or aria-label when they convey meaning; mark decorative SVGs with aria-hidden="true".
    • Do not put click handlers on non-interactive elements. Use a button or link.
    • Test keyboard navigation and visible focus states after overriding framework colors.
    • Keep class_name changes from removing focus outlines unless you provide a replacement.

    10. Testing HTML and Security

    Unit-test rendered markup without starting a server:

    from pydataui.html import P, Section

def test_quality_section_escapes_user_text():
    html = Section(P("<script>alert(1)</script>")).render({})
    assert "<script>" not in html
    assert "&lt;script&gt;" in html

    Useful test patterns:

    • Call .render({}) and assert on stable IDs, classes, and escaped content.
    • Pass an explicit id when asserting on a specific element.
    • Test hidden=True, boolean attributes, and data_* conversion.
    • Add browser coverage for layout, HTMX swaps, and responsive behavior.
    • Never use RawHtml with untrusted test fixtures unless the test is specifically verifying sanitization.
