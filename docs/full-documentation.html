01

Overview & Architecture

Traditional web frameworks force data science and backend engineering teams to maintain dual codebases: a Python backend (FastAPI/Django) and an intricate JavaScript frontend (React, Vue, Webpack, Node). PyDataUI eliminates this friction by rendering reactive HTML server-side and swapping elements dynamically using HTMX over ASGI.

🦀

High-Throughput ASGI Core

Drop-in support for both standard FastAPI and high-concurrency compiled Rust HTTP engine (PyRustAPI) delivering up to 34,000+ req/sec.

⚡

HTMX Differential Swapping

No heavy Virtual DOM or JSON serialization bundles. State changes trigger hypermedia fragment responses that morph into the browser with zero lag.

📱

Unified Cross-Platform

Deploy identical Python code across Web, Mobile PWA, native Android APK, iOS IPA (via Capacitor), and Desktop native apps (via Tauri 2.0).

🔄 PyDataUI Request-Response Cycle

1. User Event

Click, submit, or filter triggers an hx-post or hx-get.

2. ASGI Handler

PyDataUI decodes state and invokes Python handler method.

3. Server Render

Component renders clean HTML string in microseconds.

4. Target Swap

HTMX replaces #pdu-root or specific target ID.

02

Installation & Quickstart

PyDataUI requires Python 3.9 or newer. Install it via pip:

Terminal 
pip install pydataui

Your First Reactive PyDataUI Application

Create a file named app.py:

app.py 
from pydataui import App, State
from pydataui.components import Container, Card, Heading, Text, Button, Row

class Counter(State):
    count: int = 0

    def increment(self):
        self.count += 1

    def decrement(self):
        self.count -= 1

app = App(title="PyDataUI Counter", theme="dark", pwa=True)

@app.page("/")
def index(state: Counter):
    return Container(
        Card(
            Heading(f"Counter: {state.count}", level=2, class_name="text-3xl font-bold mb-4 text-white"),
            Text("Click buttons below to trigger instant hypermedia state updates.", class_name="text-slate-400 mb-6"),
            Row(
                Button("- Decrement", on_click=state.decrement, variant="secondary"),
                Button("+ Increment", on_click=state.increment, variant="primary"),
                spacing="md"
            ),
            class_name="p-8 max-w-md mx-auto text-center mt-12 bg-slate-900 border-slate-800 shadow-2xl"
        )
    )

if __name__ == "__main__":
    app.run(port=8000)

Run the app from your terminal with auto-reload:

Terminal 
pydataui run app.py --reload
03

Reactive State Engine

State in PyDataUI is defined by subclassing pydataui.State. Every field is type-annotated and automatically synced with browser sessions via signed secure cookies or session stores.

⚡ Automatic Event Binding

Passing a state method to on_click=state.my_method creates a signed hypermedia action endpoint. PyDataUI executes the method, commits state mutations, and returns the updated component fragment.

🛡️ Type Safety & Validation

Powered by Pydantic v2 underneath, input values are strictly parsed and coerced to your Python types (integers, datetimes, dataclasses, lists, dicts).

state_example.py 
class TodoState(State):
    tasks: list[str] = ["Inspect data", "Run model"]
    new_task: str = ""

    def add_task(self):
        if self.new_task.strip():
            self.tasks.append(self.new_task.strip())
            self.new_task = ""

    def delete_task(self, index: int):
        if 0 <= index < len(self.tasks):
            self.tasks.pop(index)

Mobile Apps: Android APK & iOS IPA

PyDataUI allows you to generate installable native packages (Android APK and iOS IPA) directly from the command line without opening Android Studio or Xcode.

🌐 Wi-Fi Backend Auto-Detection & Cleartext Traffic

When building for mobile, PyDataUI automatically detects your workstation's LAN IP address (e.g. http://192.168.1.50:8000) and bakes it into the Capacitor native config. Furthermore, android:usesCleartextTraffic="true" is injected into AndroidManifest.xml so the mobile OS allows instant HTTP communication back to your Python server over Wi-Fi.

✓ Wi-Fi LAN Auto-Bridge ✓ Cleartext HTTP Enabled ✓ Headless Gradle / Xcode

1. Android Build Requirements & License Acceptance

To compile Android APKs, ensure JDK 17 or JDK 21 is installed along with Android SDK Command-line Tools:

JDK Matrix (macOS / Linux)

brew install openjdk@21
sudo ln -sfn /opt/homebrew/opt/openjdk@21/libexec/openjdk.jdk \
  /Library/Java/JavaVirtualMachines/openjdk-21.jdk
export JAVA_HOME=$(/usr/libexec/java_home -v 21)

Accept Android SDK Licenses

export ANDROID_HOME=/usr/local/share/android-commandlinetools
yes | $ANDROID_HOME/cmdline-tools/latest/bin/sdkmanager --licenses

2. Compiling & Installing the Android APK

Terminal 
# 1. Compile standalone Android APK (exports to ./app-debug.apk and dist/):
pydataui mobile build --platform android

# 2. Or override target backend server:
pydataui mobile build --platform android --server-url http://192.168.1.50:8000

# 3. Directly install to connected Android device over USB/Wi-Fi via ADB:
pydataui mobile install --platform android

3. iOS IPA Packaging & Sideloading (No Paid Apple Developer Account)

PyDataUI automatically bundles your iOS app into a standard app-debug.ipa inside the workspace root and dist/:

Terminal 
pydataui mobile build --platform ios

📲 How to install app-debug.ipa on iPhone/iPad:

  1. Download Sideloadly or AltStore (macOS or Windows).
  2. Connect your iPhone via USB.
  3. Drag and drop app-debug.ipa into Sideloadly, enter your free Apple ID, and click Start.
  4. On your iPhone, go to Settings ➡️ General ➡️ VPN & Device Management and tap Trust.

4. In-Browser Device Simulator

Don't have a phone handy? Test inside an interactive browser phone chassis (iPhone 15 Pro, Pixel 8) with instant orientation toggling:

Terminal 
pydataui mobile preview app.py

Authentication & Security

PyDataUI includes built-in JWT authentication, route guarding, and automatic XSS escaping:

auth_example.py 
from pydataui import App, require_auth

app = App(auth_secret="your-production-secret-key-32-bytes")

@app.page("/dashboard")
@require_auth(roles=["admin", "analyst"])
def protected_dashboard(user):
    return Container(Heading(f"Welcome, {user.username}!"))

CLI Reference Manual

The pydataui command-line interface provides complete control over development, testing, compilation, and cloud tunnels.

pydataui run [FILE] [OPTIONS]

Run the development or production server.

--port, -p INTEGER : Port (default: 8000)
--host, -h TEXT : Host (default: 127.0.0.1)
--reload / --no-reload : Auto-reload on change
--mobile-preview : In-browser phone chassis
--desktop : Launch native webview window
--share : Tunnel URL (Cloudflare/ngrok)
pydataui mobile [init | preview | build | install] [OPTIONS]

Manage Capacitor native mobile apps.

--platform [android|ios] : Target OS
--server-url TEXT : Custom server endpoint
--port INTEGER : Port for local Wi-Fi detection
pydataui desktop [init | run | build] [OPTIONS]

Manage Tauri 2.0 Rust desktop binaries.

Production Deployment

PyDataUI apps can be deployed anywhere Python runs. Here is a production-ready Dockerfile:

Dockerfile 
FROM python:3.11-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
EXPOSE 8000
CMD ["pydataui", "run", "app.py", "--host", "0.0.0.0", "--port", "8000"]

Troubleshooting & FAQ

Q: "Warning: License for package Android SDK Build-Tools not accepted"

Run: yes | $ANDROID_HOME/cmdline-tools/latest/bin/sdkmanager --licenses to accept all Google Android SDK build licenses.

Q: "Mobile APK connects to phone's localhost instead of Mac"

PyDataUI v0.3.5 auto-detects your workstation Wi-Fi IP. Ensure your phone and workstation are on the same Wi-Fi router, or specify: pydataui mobile build --platform android --server-url http://YOUR_MAC_IP:8000.

Q: "Port 8000 already in use"

Specify a custom port: pydataui run app.py --port 8050.
