01

Overview & Architecture

PyDataUI is a modern full-stack web, mobile, and desktop framework designed for Data Engineers, Data Analysts, AI/ML Engineers, and Python developers. It eliminates the friction between toy prototype libraries (Streamlit, Gradio) and complex multi-language web stacks (React + TypeScript + FastAPI).

Write 100% Python. PyDataUI runs on standard FastAPI / Starlette ASGI by default with zero C/Rust compilation requirements, while providing an optional compiled PyRustAPI (Hyper/Tokio) engine delivering up to 34,000+ req/sec for hyper-scale production workloads.

⚡ FastAPI Default

Native ASGI on FastAPI/Uvicorn. Mount directly inside existing FastAPI apps via mount().

🦀 PyRustAPI Engine

Optional compiled Rust HTTP engine (Tokio & Hyper) delivering <1.2ms P99 latency.

⚡ HTMX Differential Swaps

Zero client JavaScript or Virtual DOM. State changes stream hypermedia fragment diffs to the DOM.

📱 Cross-Platform Native

Instant PWA, Capacitor Android APK & iOS IPA, and desktop binaries via Tauri 2.0.

02

Installation & Quickstart

Install PyDataUI in your Python 3.9+ virtual environment:

Terminal 
pip install pydataui

Create a Reactive Counter (`app.py`)

app.py 
from pydataui import App, State
from pydataui.components import Container, Card, Heading, Button, Row

class Counter(State):
    count: int = 0
    def inc(self): self.count += 1
    def dec(self): self.count -= 1

app = App(title="Counter", theme="dark", pwa=True)

@app.page("/")
def index(state: Counter):
    return Container(
        Card(
            Heading(f"Count: {state.count}", level=2, class_name="text-2xl font-bold mb-4"),
            Row(
                Button("- Dec", on_click=state.dec, variant="secondary"),
                Button("+ Inc", on_click=state.inc, variant="primary"),
                spacing="md"
            ),
            class_name="p-6 max-w-sm mx-auto text-center mt-12 bg-slate-900 border-slate-800"
        )
    )

if __name__ == "__main__":
    app.run(port=8000)
03

Reactive State Engine

State in PyDataUI is defined by subclassing pydataui.State. When a user interacts with a component, the bound Python method executes, mutates state attributes, and PyDataUI automatically sends back the updated HTML fragment.

FastAPI Mounting & Conflict Handling

PyDataUI is a pure ASGI application built natively on FastAPI and Starlette. You can mount PyDataUI dashboards, admin consoles, and AI tools into any existing FastAPI backend using a single line of code with zero route, cookie, or documentation collisions.

FastAPI + PyDataUI Native Mount 
from fastapi import FastAPI
from pydataui import App, State, mount
from pydataui.components import Container, Heading, MetricCard, Button

# 1. Existing FastAPI Backend Microservice
api = FastAPI(title="Enterprise Core API")

@api.get("/api/v1/orders")
def list_orders():
    return [{"id": 101, "amount": 450.0}]

# 2. PyDataUI Application
dashboard = App(title="Operations Dashboard", theme="dark")

@dashboard.page("/")
def home():
    return Container(
        Heading("Operations Control Center", level=1),
        MetricCard(title="Active Orders", value=142)
    )

# 3. Mount PyDataUI cleanly under /dashboard
mount(api, dashboard, path="/dashboard")
# or: dashboard.mount_to(api, path="/dashboard")

How PyDataUI Handles & Prevents Conflicts

When mounting into an existing enterprise codebase, PyDataUI applies strict namespace sandboxing across routes, documentation, static files, and cookies:

Route Collisions

If parent FastAPI has /users and PyDataUI has @app.page("/users"), there is zero clash. PyDataUI routes are strictly nested under /dashboard/users via Starlette ASGI delegation.

Swagger / OpenAPI Separation

Parent API keeps its root Swagger UI at /docs. PyDataUI automatically serves its dedicated OpenAPI schema and explorer at /dashboard/docs without overwriting parent schemas.

Static Asset Sandboxing

PyDataUI bundles all internal Tailwind CSS, HTMX, and icons under /_pdu/static/*. It never interferes with parent FastAPI app.mount("/static", ...) directories.

Session & Cookie Scoping

PyDataUI state sessions use a dedicated, signed cookie pdu-session with HttpOnly and SameSite=Lax. Parent JWT tokens or custom auth cookies are never overwritten.

Production Build & Containerization

Package your application into self-contained Docker containers and production assets with pydataui build:

Production Packaging Pipeline 
# 1. Package production bundle with offline static files & Dockerfile:
pydataui build app.py --output dist

# 2. Deploy containerized service with Docker Compose:
cd dist && docker compose up --build -d

Native Android APK & iOS IPA

Terminal 
# 1. Compile headless Android APK (exports to ./app-debug.apk):
pydataui mobile build --platform android

# 2. Install to connected device via ADB:
pydataui mobile install --platform android

# 3. Package iOS IPA for free sideloading:
pydataui mobile build --platform ios
